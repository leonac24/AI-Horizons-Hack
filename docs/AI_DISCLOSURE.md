# AI disclosure

## AI used to build Lotline

- **Claude Code (Anthropic, Claude Opus 5.5)** wrote most of the first-pass code
  and docs, working with the team: the pipeline, engine, API, frontend and
  tests. A person on the team decided each design question. Code was
  checked by the test suite (config validation, scoring math, zoning evaluation,
  a citywide coverage test, a no-hardcoding fixture) and by running the app.
- The 3D simulator was built from a design handoff (an HTML/three.js
  prototype) that the team supplied. Claude Code ported it to the repo's
  React/TypeScript code. It replaced the prototype's placeholder model and
  sample zoning rules with API data, because those were invented and are not
  shipped.
- Claude Code also looked up and checked the dataset endpoints listed in
  `sources.yaml`, calling the WPRDC CKAN API directly.

## AI inside Lotline

| Where | Model | What it may do | How it's checked |
|---|---|---|---|
| Zoning extraction (offline, `pipeline/zoning/extract.py`) | Claude via the Anthropic API, `ZONING_EXTRACT_MODEL` (default `claude-opus-5`) | Read Title Nine text and propose per-district rules | The API constrains output to a JSON schema whose use and rule keys come from `zoning.yaml`, and it is validated again locally. Each rule must quote the source verbatim (< 25 words) or it is dropped. Rules are in force once they pass these checks and the UI labels each answer "AI-extracted …; not checked by a planner". With `require_human_review: true` only rules a person marked `reviewed: true` count. |
| Source passage classification (offline, `pipeline/laya_compile.py`) | Laya, local `typed-decisions` checkpoint by default | Sort public zoning and source-document passages into evidence topics | The checked-in artifact contains source hashes, short excerpts and links. Labels are displayed as leads only; they cannot change metrics, zoning status, or rankings. |
| Tradeoff explanations (runtime, `server/explain.py`) | Claude via the Anthropic API, `LLM_MODEL` (default `claude-opus-5`) | Restate computed metrics as plain-language tradeoffs | Every sentence must cite metric IDs from the input and use only numbers from the input. If not, the server discards the output and shows a deterministic template. The UI says which one you're seeing. |

- With `LLM_PROVIDER=none` the app runs with no AI at runtime.
- **Data sent to Anthropic:** only public information. That is zoning code
  text, or computed metrics for a public parcel together with the user's current
  slider weights. No personal data.
- **Current zoning rules were not produced by `extract.py`.** The rules in
  `rules_review.yaml` today were generated by `pipeline/zoning/build_rules.py`
  from hand-extracted facts (`extracted_by: claude-code`). The extraction script
  above has not been run over them yet.
- **What AI never does here:** set a weight, change a metric, or rank options.
- **What AI does decide:** zoning status. AI-extracted rules give the approval
  path and can exclude a prohibited option from the ranking, without a person
  checking them first (`require_human_review: false`). Every such answer is
  labelled as AI-extracted and not checked by a planner, cites its section and
  quotes the code, and the site-wide banner says to confirm with City Planning.
  A check of every fact against the saved code text (2026-09-27) found and
  fixed one error (the R1A Very Low density side yard).

## Zoning rules (2026-09-26)

- **Who extracted them:** Claude Code, by hand. It read Title Nine on eCode360
  through the team's browser, because the site blocks scripted requests.
- **What each fact carries:** its section, a dated snapshot of the source text
  (`data/sources/zoning/`) and verbatim quotes. `pipeline/zoning/build_rules.py`
  refuses to build if any quote is 25 words or longer, or isn't found word for
  word in its snapshot.
- **What counts:** every fact whose quotes verify. A person can still confirm
  facts in `pipeline/zoning/REVIEW.md` (`--apply` records their name and date);
  confirmed answers lose the "not checked by a planner" label. Turning on
  `require_human_review` makes only confirmed facts count.
